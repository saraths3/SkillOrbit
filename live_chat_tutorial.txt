================================================================================
          DJANGO CHANNELS & WEBSOCKETS: THE ULTIMATE GUIDE FOR DJANGO DEVELOPERS
================================================================================

Welcome! As a Django developer, you already know models.py, views.py, urls.py, 
and settings.py. This guide maps EVERYTHING you know in traditional Django 
directly to Django Channels and WebSockets.

Read this file from top to bottom. By the end, you will be able to build a 
real-time live chat system in any Django project without any confusion.

================================================================================
PART 1: THE "ROSETTA STONE" (DJANGO HTTP vs DJANGO CHANNELS)
================================================================================

If you know traditional Django, here is how every piece maps to Django Channels:

--------------------------------------------------------------------------------
TRADITIONAL DJANGO (HTTP)       --->  DJANGO CHANNELS (WEBSOCKETS)
--------------------------------------------------------------------------------
wsgi.py                         --->  asgi.py
urls.py                         --->  routing.py
views.py                        --->  consumers.py
def my_view(request):           --->  class ChatConsumer(AsyncWebsocketConsumer):
request (HttpRequest object)    --->  self.scope (dict containing user, session, url)
HttpResponse / render()         --->  self.send() (Pushes JSON data to browser)
request.user                    --->  self.scope["user"]
urls.py path('chat/<id>/', ...) --->  routing.py re_path(r'ws/chat/(?P<id>\d+)/')
DATABASES in settings.py        --->  CHANNEL_LAYERS in settings.py
--------------------------------------------------------------------------------

MENTAL MODEL:
- In Django views.py, a HTTP GET request comes in -> view processes data -> returns HttpResponse -> connection closes.
- In Django consumers.py, a WebSocket connection opens -> stays open indefinitely -> connect() runs on open, receive() runs whenever a message arrives, disconnect() runs when closed.

--------------------------------------------------------------------------------
STEP 1: INSTALL REQUIRED PACKAGES
--------------------------------------------------------------------------------
In your virtual environment terminal, run:

    pip install channels daphne channels_redis

- `daphne`: The ASGI server that accepts WebSockets (`ws://`) connections.
- `channels`: The Django Channels framework.
- `channels_redis`: The Channel Layer backend for Redis (optional for dev, needed for prod).


--------------------------------------------------------------------------------
STEP 2: UPDATE `settings.py`
--------------------------------------------------------------------------------
Open `<YOUR_PROJECT_NAME>/settings.py`:

1. Add `'daphne'` as the VERY FIRST app in `INSTALLED_APPS` (above `django.contrib.staticfiles`), and add `'channels'`:

   INSTALLED_APPS = [
       'daphne',                 # [CRITICAL] MUST be first so runserver uses ASGI!
       '<YOUR_APP_NAME>',        # Your chat app (e.g. 'chat')
       'channels',               # Django Channels engine
       'django.contrib.admin',
       'django.contrib.auth',
       'django.contrib.contenttypes',
       'django.contrib.sessions',
       'django.contrib.messages',
       'django.contrib.staticfiles',
   ]

2. Set the `ASGI_APPLICATION` setting (tells Django where `asgi.py` is located):

   ASGI_APPLICATION = '<YOUR_PROJECT_NAME>.asgi.application'

3. Define `CHANNEL_LAYERS` (Think of this like `DATABASES`, but for live message broadcasting):

   # FOR LOCAL DEVELOPMENT (Zero external setup required):
   CHANNEL_LAYERS = {
       "default": {
           "BACKEND": "channels.layers.InMemoryChannelLayer",
       },
   }

   # FOR PRODUCTION (When using Redis server):
   # CHANNEL_LAYERS = {
   #     "default": {
   #         "BACKEND": "channels_redis.core.RedisChannelLayer",
   #         "CONFIG": {
   #             "hosts": [("127.0.0.1", 6379)],
   #         },
   #     },
   # }


--------------------------------------------------------------------------------
STEP 3: CONFIGURE `asgi.py` (The ASGI Entry Point)
--------------------------------------------------------------------------------
Open `<YOUR_PROJECT_NAME>/asgi.py`.

In standard Django, `wsgi.py` handles HTTP. In Django Channels, `asgi.py` acts as 
a master traffic controller that routes HTTP requests to Django, and WebSocket 
requests (`ws://`) to Channels.

Replace `<YOUR_PROJECT_NAME>/asgi.py` with:

```python
import os
from django.core.asgi import get_asgi_application
from channels.routing import ProtocolTypeRouter, URLRouter
from channels.auth import AuthMiddlewareStack
import <YOUR_APP_NAME>.routing   # Import routing.py from your chat app

os.environ.setdefault('DJANGO_SETTINGS_MODULE', '<YOUR_PROJECT_NAME>.settings')

# 1. Initialize standard Django HTTP ASGI application early
django_asgi_app = get_asgi_application()

# 2. ProtocolTypeRouter routes HTTP -> Django, and WebSocket -> Channels
application = ProtocolTypeRouter({
    "http": django_asgi_app,
    "websocket": AuthMiddlewareStack(
        URLRouter(
            <YOUR_APP_NAME>.routing.websocket_urlpatterns
        )
    ),
})
```

WHAT THIS DOES:
- `ProtocolTypeRouter`: Checks the incoming request type (`http` vs `websocket`).
- `AuthMiddlewareStack`: Populates `request.user` equivalent inside WebSockets (`self.scope["user"]`).
- `URLRouter`: Passes WebSocket URLs to your app's `routing.py`.


--------------------------------------------------------------------------------
STEP 4: CREATE CHAT MODELS (`<YOUR_APP_NAME>/models.py`)
--------------------------------------------------------------------------------
Define your conversation and message models as standard Django models:

```python
from django.db import models
from django.contrib.auth import get_user_model

User = get_user_model()

class Conversation(models.Model):
    user_one = models.ForeignKey(User, on_delete=models.CASCADE, related_name='conversations_as_user_one')
    user_two = models.ForeignKey(User, on_delete=models.CASCADE, related_name='conversations_as_user_two')
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        unique_together = ('user_one', 'user_two')

class Message(models.Model):
    conversation = models.ForeignKey(Conversation, on_delete=models.CASCADE, related_name='messages')
    sender = models.ForeignKey(User, on_delete=models.CASCADE)
    message = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        ordering = ['created_at']
```


--------------------------------------------------------------------------------
STEP 5: CREATE WEBSOCKET ROUTING (`<YOUR_APP_NAME>/routing.py`)
--------------------------------------------------------------------------------
Create a new file named `routing.py` inside your app directory `<YOUR_APP_NAME>/routing.py`.

Just like `urls.py` maps HTTP URLs to views, `routing.py` maps WebSocket URLs to Consumers!

```python
from django.urls import re_path
from . import consumers

websocket_urlpatterns = [
    # Maps ws://domain.com/ws/chat/5/ to ChatConsumer
    re_path(r'ws/chat/(?P<target_user_id>\d+)/$', consumers.ChatConsumer.as_asgi()),
]
```

EXPLANATION:
- `(?P<target_user_id>\d+)`: Captures the ID of the user you are chatting with from the URL, accessible in `consumers.py` as `self.scope['url_route']['kwargs']['target_user_id']`.


--------------------------------------------------------------------------------
STEP 6: WRITE THE CONSUMER (`<YOUR_APP_NAME>/consumers.py`)
--------------------------------------------------------------------------------
Create a file named `consumers.py` inside `<YOUR_APP_NAME>/consumers.py`.

Think of `ChatConsumer` as a Django `View`, but with 3 main lifecycle methods:
  1. `connect()`   : Triggered when the browser opens a WebSocket connection (`new WebSocket()`).
  2. `receive()`   : Triggered whenever the browser sends data (`socket.send()`).
  3. `disconnect()`: Triggered when the browser closes the tab or disconnects.

Here is the exact code:

```python
import json
from channels.generic.websocket import AsyncWebsocketConsumer
from channels.db import database_sync_to_async
from django.contrib.auth import get_user_model
from .models import Conversation, Message

User = get_user_model()

class ChatConsumer(AsyncWebsocketConsumer):

    # --------------------------------------------------------------------------
    # 1. CONNECT (Runs when WebSocket connection is opened)
    # --------------------------------------------------------------------------
    async def connect(self):
        # self.scope["user"] is populated by AuthMiddlewareStack (like request.user)
        self.user = self.scope["user"]

        # Security Guard: Reject unauthenticated users
        if not self.user.is_authenticated:
            await self.close()
            return

        # Extract target_user_id from the URL (from routing.py regex pattern)
        self.target_user_id = self.scope['url_route']['kwargs']['target_user_id']

        # Deterministic Group Naming: Ensure User 3 & User 7 get same group name "chat_3_7"
        user_ids = sorted([self.user.id, int(self.target_user_id)])
        self.room_group_name = f"chat_{user_ids[0]}_{user_ids[1]}"

        # Join the channel layer group
        await self.channel_layer.group_add(
            self.room_group_name,
            self.channel_name
        )

        # Accept the WebSocket connection handshake
        await self.accept()

    # --------------------------------------------------------------------------
    # 2. DISCONNECT (Runs when WebSocket connection closes)
    # --------------------------------------------------------------------------
    async def disconnect(self, close_code):
        if hasattr(self, 'room_group_name'):
            # Remove connection from group
            await self.channel_layer.group_discard(
                self.room_group_name,
                self.channel_name
            )

    # --------------------------------------------------------------------------
    # 3. RECEIVE (Runs when browser sends data via socket.send())
    # --------------------------------------------------------------------------
    async def receive(self, text_data):
        data = json.loads(text_data)
        message_body = data.get('message', '').strip()

        if not message_body:
            return

        # Save to database using async wrapper (explained below)
        saved_msg = await self.save_message(self.user.id, int(self.target_user_id), message_body)

        # Broadcast the message to all members in the group "chat_3_7"
        await self.channel_layer.group_send(
            self.room_group_name,
            {
                'type': 'chat_message',  # Triggers chat_message() method below!
                'message': saved_msg.message,
                'sender_id': self.user.id,
                'sender_username': self.user.username,
                'created_at': saved_msg.created_at.strftime('%I:%M %p')
            }
        )

    # --------------------------------------------------------------------------
    # 4. CHAT_MESSAGE (Group Broadcast Handler)
    # --------------------------------------------------------------------------
    async def chat_message(self, event):
        # Sends the broadcast payload down the WebSocket to the browser
        await self.send(text_data=json.dumps({
            'message': event['message'],
            'sender_id': event['sender_id'],
            'sender_username': event['sender_username'],
            'created_at': event['created_at']
        }))

    # --------------------------------------------------------------------------
    # 5. ORM HELPER (@database_sync_to_async)
    # --------------------------------------------------------------------------
    @database_sync_to_async
    def save_message(self, sender_id, recipient_id, text):
        """
        Django ORM calls are synchronous. Since AsyncWebsocketConsumer is async,
        we MUST wrap Django ORM database queries in @database_sync_to_async!
        """
        sender = User.objects.get(id=sender_id)
        recipient = User.objects.get(id=recipient_id)

        user_one, user_two = (sender, recipient) if sender.id < recipient.id else (recipient, sender)
        conversation, _ = Conversation.objects.get_or_create(user_one=user_one, user_two=user_two)

        return Message.objects.create(
            conversation=conversation,
            sender=sender,
            message=text
        )
```


--------------------------------------------------------------------------------
STEP 7: FRONTEND HTML & JAVASCRIPT WEBSOCKET CLIENT (`chat.html`)
--------------------------------------------------------------------------------
In your template `templates/<YOUR_APP_NAME>/chat.html`:

```html
{% extends 'base.html' %}

{% block content %}
<div class="chat-container">
    <div id="chat-box" style="height: 400px; overflow-y: auto;">
        {% for msg in chat_messages %}
            <div class="{% if msg.sender == request.user %}my-message{% else %}other-message{% endif %}">
                <p>{{ msg.message }}</p>
                <small>{{ msg.created_at|date:"h:i A" }}</small>
            </div>
        {% endfor %}
    </div>

    <form id="chat-form">
        <input type="text" id="message-input" placeholder="Type a message..." required>
        <button type="submit">Send</button>
    </form>
</div>

<script>
    const targetUserId = "{{ user_two.id }}";
    const currentUserId = "{{ request.user.id }}";
    const chatBox = document.getElementById("chat-box");
    const chatForm = document.getElementById("chat-form");
    const messageInput = document.getElementById("message-input");

    // 1. Detect HTTP vs HTTPS to choose ws:// or wss://
    const wsProtocol = window.location.protocol === 'https:' ? 'wss://' : 'ws://';
    
    // 2. Open WebSocket connection to ASGI Daphne server
    const chatSocket = new WebSocket(
        wsProtocol + window.location.host + "/ws/chat/" + targetUserId + "/"
    );

    // 3. Receive live broadcasts from server
    chatSocket.onmessage = function(e) {
        const data = JSON.parse(e.data);

        // Convert both IDs to strings for accurate comparison
        const isSelf = String(data.sender_id) === String(currentUserId);
        const messageClass = isSelf ? "my-message" : "other-message";

        const msgDiv = document.createElement("div");
        msgDiv.className = messageClass;
        msgDiv.innerHTML = `<p>${data.message}</p><small>${data.created_at}</small>`;

        chatBox.appendChild(msgDiv);
        chatBox.scrollTop = chatBox.scrollHeight;
    };

    // 4. Send message when user submits form (or presses Enter)
    chatForm.addEventListener("submit", function(e) {
        e.preventDefault();
        const text = messageInput.value.trim();

        if (text !== "" && chatSocket.readyState === WebSocket.OPEN) {
            chatSocket.send(JSON.stringify({ "message": text }));
            messageInput.value = "";
        }
    });
</script>
{% endblock %}
```


================================================================================
PART 4: LIFECYCLE WALKTHROUGH (WHAT HAPPENS WHEN YOU SEND A MESSAGE)
================================================================================

1. USER ACTION: User A types "Hello!" in browser and presses Enter.
2. FRONTEND JS: `chatForm` event listener intercepts Enter key -> executes `chatSocket.send(JSON.stringify({"message": "Hello!"}))`.
3. ASGI ROUTER: `asgi.py` passes the WebSocket frame to `chat/routing.py` -> routes to `ChatConsumer`.
4. RECEIVE METHOD: `ChatConsumer.receive()` runs:
   - Saves message to Database via `save_message()` (`@database_sync_to_async`).
   - Calls `self.channel_layer.group_send("chat_3_7", {"type": "chat_message", ...})`.
5. BROADCAST HANDLER: `ChatConsumer.chat_message()` executes for ALL active users connected to group `"chat_3_7"` (User A & User B).
6. FRONTEND UPDATE: User B's browser triggers `chatSocket.onmessage` -> appends `<p>Hello!</p>` to User B's chat window INSTANTLY without page refresh!


================================================================================
PART 5: TROUBLESHOOTING & COMMON PITFALLS CHECKLIST
================================================================================

[ ] 1. 'daphne' MUST be at the top of INSTALLED_APPS in settings.py.
       If it is below `django.contrib.staticfiles`, runserver will default to WSGI (no WebSockets!).

[ ] 2. Django ORM in Async Consumers:
       ALWAYS use `@database_sync_to_async` when querying models inside `AsyncWebsocketConsumer`. Never call `Message.objects.create()` directly in an `async def` function without `@database_sync_to_async`.

[ ] 3. ID Comparison in JavaScript:
       Always use `String(data.sender_id) === String(currentUserId)` in JavaScript. JavaScript considers `3 === "3"` to be FALSE unless converted to String.

[ ] 4. Development vs Production Channel Layer:
       In development, use `InMemoryChannelLayer`. In production (multiple server instances), use `RedisChannelLayer`.
